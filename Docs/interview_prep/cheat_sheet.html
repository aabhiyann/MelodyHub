🗣️ The "Golden Answers" (Read These)

"Tell me about testing on this project."

"We use a Testing Pyramid strategy. For the Backend, I use Jest and Supertest with an in-memory MongoDB to test API integration. For the Frontend, I use Vitest and React Testing Library to test UI components like the Search bar."

"Why Vitest instead of Jest?"

"Speed and config. Since we use Vite as our build tool, Vitest reuses the same configuration. It is much faster and avoids the complex setup issues Jest has with TypeScript."

"What is Regression Testing?"

"It's simply running our existing suite of tests to make sure new code doesn't break old features. I run `npm test` before every commit."

🧠 Key Concepts (The "What")

Unit Testing

Definition: Testing one tiny function in isolation.

Example: `formatDuration(65)` returns `"1:05"`.

Integration Testing

Definition: Testing how parts work together (API + DB).

Example: Signing up a user actually creates a record in the database.

Mocking

Definition: Faking a complex part (like a DB) to test logic.

Tools: `vi.fn()` or `jest.fn()`.

Analogy: Using a crash test dummy instead of a real person.

Backend Integration (Jest)

it('should save a user', async () => {
  // 1. Send Fake Request
  const res = await request(app)
    .post('/api/login')
    .send(userData);

  const user = await User.findOne({

});

Frontend Component (Vitest)

it('renders search results', async () => {
  // 1. Render Component
  render(<SearchPage />);
  
  // 2. Type "Rock"
  await userEvent.type(
    screen.getByRole('textbox'), 
    'Rock'
  );

  // 3. Verify Result
  expect(screen.getByText('Rock Song'))
    .toBeInTheDocument();
});
